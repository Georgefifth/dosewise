# FormPilot — InfinityX Global Hackathon 2K26

**Tagline:** Paperwork, translated. AI copilot that turns intimidating government, insurance, and medical forms into a guided, plain-language conversation — then fills the real PDF for you.

## The Problem

Every year, billions of dollars in benefits go unclaimed and applications get rejected — not because people are ineligible, but because forms are written in bureaucratic language, fields are cryptic (`appl_sgnltr_fid_2`), and instructions assume native-level literacy. This hits hardest for immigrants, seniors, low-literacy users, and anyone facing a form in a language they don't fully speak.

## The Solution

Upload a fillable PDF form → FormPilot extracts the real AcroForm fields → an AI layer translates each field into a plain-language question (in the user's chosen language) → a guided interview collects answers one at a time while highlighting the exact field on the document → FormPilot fills the actual PDF and produces a plain-language summary of everything submitted. A local "vault" remembers answers (name, address, DOB…) so the next form is mostly already done.

## Judging-criteria map (InfinityX 2K26, deadline Sep 25 2026 @ 11:45pm IST)

- **Innovation:** field-level grounding — every question highlights the exact widget on the PDF; "why is this asked?" jargon-buster per field; multilingual interview around a monolingual form.
- **Technical:** real AcroForm parsing/filling via pdf-lib, pdfjs viewer with widget-rect overlays, OpenAI-compatible LLM layer with deterministic offline fallback.
- **Impact:** benefits access, healthcare intake, immigration paperwork — measurable story ($140B+/yr unclaimed US benefits).
- **UX:** one-question-at-a-time flow, progress, skip, large-type mode, voice input (Web Speech API).
- **Submission needs:** live demo, ≤5min demo video, GitHub repo w/ README, screenshots.

## Architecture

- **Next.js (App Router) + TypeScript + Tailwind** — single deployable.
- `app/api/*` — server routes hold LLM keys (never shipped to client).
- `lib/pdf.ts` — AcroForm field extraction + filling (pdf-lib).
- `lib/llm.ts` — provider abstraction: OpenAI-compatible endpoint (`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`); deterministic mock when unset so the demo NEVER breaks.
- `lib/schema.ts` — `FormField`, `InterviewPlan`, `Answer` types shared client/server.
- `components/` — `PdfViewer` (pdfjs + widget highlight overlay), `Interview` (chat-style question flow), `UploadDropzone`, `FieldReview` (edit answers in a table), `SummaryCard`.
- `public/samples/*.pdf` — bundled sample AcroForm PDFs generated by `scripts/make-samples.ts` so the demo works offline with zero upload.

## Commands

- `pnpm dev` — dev server on :3000
- `pnpm build` / `pnpm lint` / `pnpm typecheck`
- `pnpm tsx scripts/make-samples.ts` — regenerate sample PDFs

## Conventions

- No secrets in client code or commits. `.env.local` is gitignored; ship `.env.example`.
- Mock LLM path must stay feature-complete — judges may run without keys.
- Keep the interview deterministic-ordered; LLM only rephrases/enriches, never reorders required fields.
- Commit early/often; demo > architecture purity. Optimize for the 5-minute video story: upload → wow moment (field highlight) → multilingual question → filled PDF download.
